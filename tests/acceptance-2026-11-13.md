# 双竖屏真机验收 · 2026-11-13

环境：macOS 26.6.2（25G83）；HP M27P 主屏 2048×1152 点，两个 27B1U3900L 竖屏各 1296×2304 点，2×、60 Hz。

验收使用两个独立 AppKit 测试应用，每个应用提供两个窗口。通过实际 App 面板选窗、点击测试窗口退出全屏，读取测试应用自己的窗口状态和全屏事件记录；没有用脚本直接调用产品会话方法代替 UI 流程。

| 场景 | 实测结果 |
| --- | --- |
| 未拆分竖屏 → 快捷组合 → 下方退出全屏 | 通过。两个窗口分别进入原生全屏；下方退出后约 2.15 秒，上方也退出；两个窗口回到主屏，原位置和尺寸一致。 |
| 先拆分桌面 → 快捷组合 → 上方退出全屏 | 通过。下方约 2.82 秒后退出；窗口回原处，桌面拆分保留。虚拟屏 196/197 没有重建，位置不变；界面明确显示保留桌面拆分。 |
| 两块竖屏同时快捷全屏，先结束右侧 | 通过。右侧自动还原；左侧窗口持续全屏，显示器 ID、窗口尺寸和位置不变，没有额外全屏切换事件。 |
| 再次双屏全屏，结束左侧临时组合 | 通过。左侧恢复窗口并保留桌面；右侧状态及窗口几何不变。 |
| 右侧仍全屏时，完整合并左侧桌面 | 通过。左侧物理屏恢复原位置；右侧窗口仍保持 198/199 上的全屏，位置、尺寸及全屏事件不变。 |
| 结束最后一组 | 通过。测试窗口退出全屏；虚拟屏和闲置半屏全部释放，只剩原来的三个物理显示器；恢复记录文件已删除。 |
| 最近组合复用 | 通过。在面板按回车成功复用右侧组合。 |

最后物理屏排列：主屏 `(0,0)`；左竖屏 `(-1296,-400)`；右竖屏 `(2048,-360)`，与开始前一致。测试应用已退出。没有关闭用户的工作应用。

## 发现并修复

- 某些应用尚未发布可用的辅助功能窗口列表。选择时补充让出激活权、激活应用和定位窗口，避免仅重复读取空列表。
- 显示器重排后的辅助功能句柄可能失效。迁移与恢复时重新定位窗口，保留精确窗口 ID 匹配。
- 恢复全屏时原逻辑只移动窗口位置。现在同时适配目标屏尺寸，激活目标窗口，在后台限时确认全屏稳定；辅助功能查询不再长时间阻塞主线程。
- 快捷组合期间，不再把原屏上无关窗口重新推入全屏；其原全屏状态在组合结束时恢复。长期桌面拆分仍恢复这些窗口的全屏状态。
- 初次拆分包含原窗口迁移、显示器创建和全屏转换，总准备时限调整为 45 秒；已有桌面上的临时组合仍为 20 秒。正常实测进入耗时明显低于该上限。

早期失败均先完成恢复重试，再继续下一轮。上述表格是修复后的复测结果。
